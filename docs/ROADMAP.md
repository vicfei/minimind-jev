# ROADMAP — minimind-jev 全阶段规划

> 原则：每个阶段的产出都独立可发布；诚实标注"从零"的边界；评测永远走
> jev-rag-zh-benchmark 协议（同样本、同指标、同置信区间）。

## v0.1 — 冻结编码器 + 从零决策头（当前，训练机执行）

- 数据：T2Reranking 难负例，二元标签（数据集自带），题目措辞冻结自模式库 noul-zh 变体
- 已完成（本机）：数据构造验证（1656/183 查询划分，seed 42）、训练/评测脚本、CI
- 训练机执行 → 回传 head.pt → 本机评测出三方表
- **发布形态**：三方表 + 校准分析。即使 minimind-jev 输给 Jev-1.13 也是可发布结果
  （"一个 CPU 训练的头能到 hosted 模型的百分之多少"本身就是中文社区想知道的数字）

## v0.2 — 蒸馏多任务（API 工作，可在本机执行，无需 GPU）

教师：deepseek-flash（已有 key）。对学生对 (query, passage) 按模式库 score-zh 四级评分尺打分，
产出软标签（四级概率分布）。

- 数据量：1839 查询 × 10 段 ≈ 18,390 次教师调用
- 成本估算：~900 token/次 × 18.4K ≈ 16.5M 输入 token，flash 档位 **< ¥5**
- 产出：`data/distilled.jsonl`（含四级软标签）→ 训练机一次会话可同时训 v0.1（硬标签）和 v0.2（软标签）双头
- 教师提示词已定稿（见 issue #2），输出直接是 JSON 四级概率，解析失败率进日志
- **状态（2026-10-21）**：E2a 完成——蒸馏数据已全量生成并入库（`data/distilled.jsonl`，17,390 对、
  零失败、~¥8 谷时成本；池化调用 + 关推理通道，逐对调用方案会要 ~¥56）。教师期望分分离度
  AUC≈0.716，与 hosted Jev（0.714–0.718）同档。下一步：训练机 Phase 2（`train_v2.py` 双头）。
- **启动条件**：你说"跑"就开（约 1 小时 API 时间）

## v0.3 — 从零 transformer（GPU，minimind 纯血形态）

- 架构：4–6 层、d_model 256、~15M 参数、上下文 1024，自有 BPE 词表（中文 ~8K）
- 训练目标：选项打分（不生成 token）——比 minimind 的 LLM 任务小一个数量级，
  单卡 2 小时的故事可复制
- 数据扩充：v0.1 的 18K 对 + v0.2 蒸馏 18K 对 + （可选）DuRetrieval 增广
- 教程：**中文章节化**（这是 minimind 的真正护城河，v0.3 的核心交付不是模型是教程）：
  0. 决策模型不是聊天模型：System One 心智模型
  1. 从 T2Reranking 到类型化问答：数据构造（含"问题设计"一节，引用模式库 51 条）
  2. 分词器与词表：从零训练 BPE
  3. 白盒实现一个最小的选项打分 transformer
  4. 训练循环：损失、温度校准、早停——校准即特性，不是补丁
  5. 评测：接基准协议，三方对比表怎么读
  6. 蒸馏进阶：让大模型当评分老师
  7. 部署：导出 ONNX 在浏览器里跑（呼应 jev-omni.js 的形态）
  每章带成本锚定（"两小时、单卡、X 块钱"）
- **启动条件**：v0.1 三方表数字成立 + 你确认 GPU 机器

## 命名与定位

- `minimind-jev`：向 minimind 系列致敬的命名（README 已注明 in the spirit of，非官方关联）
- 与生态既有物区分：MiniJev/NanoJev（复现）、Valen（研究级训练器）、
  本项目（中文教育向 + 挂接自有基准与模式库的完整闭环）
- 三仓飞轮：模式库出题目 → 基准出评测 → minimind-jev 出模型 → 模型结果反哺 arXiv v2
